## Назначение приложения

TerrainGen создаёт и редактирует карты высот для дальнейшего использования в Substrata/Metasiberia:

1. Генерирует процедурные острова, континенты, каньоны, дельты и другие формы.
2. Импортирует реальный рельеф из выделенной области карты.
3. Позволяет скульптить высоту кистями и штампами.
4. Создаёт и вручную редактирует RGB-маску материалов.
5. Создаёт и вручную редактирует чёрно-белую маску деревьев.
6. Показывает 2D и интерактивное 3D-превью.
7. Экспортирует EXR, PNG-маски, PNG-превью, JSON-проект и ZIP-пакет.

Важные особенности сети:

- Photon может возвращать HTTP 400 при `lang=ru`. Поэтому русские запросы идут без `lang`, английские — с `lang=en`; при 400 выполняется повтор без параметра языка.
- Open-Meteo может отвечать HTTP 429. Основной импорт должен сначала пробовать Terrarium, а Open-Meteo использовать как резерв.
- Картографические запросы зависят от CORS, сети и лимитов внешних сервисов. Ошибка сети не должна повреждать текущий рельеф.
- При смене слоя выделение, поисковый маркер и остальные overlay-слои должны оставаться поверх карты: см. `bringGeoOverlaysToFront()`.

## Модель данных

### Авторитетные массивы

Все массивы объявлены в строках 760–766 и имеют размер, зависящий от `G`.

| Переменная | Тип/размер | Значение |
| --- | --- | --- |
| `G` | число, по умолчанию 512 | Внутренняя квадратная сетка скульпта |
| `OUT` | число, по умолчанию 1024 | Разрешение каждого экспортируемого файла в пикселях |
| `PRE` | число, 192 | Целевой предел детализации 3D-превью; историческая переменная |
| `worldSize` | число, по умолчанию 8192 м | Максимальная физическая сторона террейна |
| `terrainAspect` | число | Отношение ширины к высоте, сохраняющее прямоугольный импорт |
| `height` | `Float32Array(G*G)` | Единственный источник высоты, реальные метры |
| `autoRGB` | `Uint8ClampedArray(G*G*3)` | Автоматически рассчитанные материалы |
| `maskRGB` | `Uint8ClampedArray(G*G*3)` | Итоговая отображаемая и экспортируемая RGB-маска |
| `overrideA` | `Uint8ClampedArray(G*G)` | 0 = автоматический материал, 255 = ручной материал |
| `treeMask` | `Uint8ClampedArray(G*G)` | 0 = AUTO, 128 = принудительно разрешить, 255 = принудительно запретить |
| `treeAutoMask` | `Uint8ClampedArray(G*G)` | Автоматический лес: 255 = разрешён, 0 = запрещён |

### Главные инварианты

1. `height` всегда хранит метры. Масштаб `pHeightScale` влияет только на 3D-превью и подсказку для Substrata, не на экспортируемые значения.
2. `height`, `overrideA`, `treeMask` и `treeAutoMask` всегда имеют ровно `G*G` элементов; `autoRGB` и `maskRGB` — `G*G*3`.
3. Любое изменение `G` обязано пересоздать и согласованно перенести все эти массивы. Эталон — `resizeGrid()`, строки 3439–3463.
4. Обычный material pixel имеет сумму R+G+B = 255; `normalizeMaterialPixel()`, строки 2662–2672, обеспечивает это для ручной покраски. Единственное допустимое исключение — `[0,0,0]`, которым `applyForestToMaterialMask()` намеренно кодирует внешний `detail 3` (открытая трава без деревьев).
5. Каналы материалов фиксированы: R = rock/detail 0, G = sediment/detail 1, B = vegetation/detail 2.
6. Разрешение дерева зависит и от tree mask, и от растительного B-канала. Инструмент `treeAdd` намеренно меняет обе маски.
7. Ручной материал (`overrideA != 0`) нельзя молча перезаписывать автоматической генерацией леса или склонов.
8. Перед первой мутацией пользовательского действия нужен `snapshot()`. Не делать snapshot на каждой промежуточной точке drag.
9. После изменения высоты обычно нужны: `refreshVisualPeak()`, автоматические маски, `dirty3d=true`, `dirtyPreview3d=true`, `render2d()`, `updateUndoButtons()` и понятный status.
10. `terrainAspect` должен сохранять географическое соотношение сторон. Нельзя снова растягивать прямоугольный импорт в квадрат.
11. Кисть должна выглядеть кругом на экране даже при прямоугольном terrain aspect. Использовать `terrainBrushRadii()`, `terrainBrushOffset()` и `terrainBrushDistance()`, а не простой круг в координатах сетки.
12. Ошибка импорта карты не должна частично заменять текущие данные.

## Основной поток данных

### Процедурный террейн

`выбор острова/формы` → `makeTemplate(kind)` → `shapeField()` + `landHeight()` → `naturalizeHeightField()` → очистка ручных масок → `generateAutoMask()` → `buildAutomaticForestMask()` / `applyForestToMaterialMask()` → `render2d()`.

Код:

- шумовые функции: строки 873–976;
- базовая высота суши: `landHeight()`, 1057–1072;
- геометрия всех форм: `shapeField()`, 1073–1390;
- эрозия/сглаживание после генерации: `naturalizeHeightField()`, 1391–1450;
- подписи и выбор вида острова: 1451–1461;
- окончательная генерация: `makeTemplate()`, 1462–1596.

### Реальный террейн

`выделение Leaflet` → вычисление bounds и реального aspect → запрос Terrarium → при ошибке Open-Meteo → интерполяция в `height` → необязательная маска острова/шельфа → сброс зависимых масок → сохранение `geoSourceMeta` → возврат в редактор.

Главная функция: `importGeoSelection()`, строки 2388–2454.

### Скульпт

`pointerdown` → один `snapshot()` + `beginSculptStroke()` → интерполированные вызовы `stampHeight()` → `applyStampAt()` → при `pointerup` `endSculptStroke()` → обновление авто-материалов/рендера.

Основной код: строки 2455–2661 и 2755–2806.

### Материалы и деревья

Один обработчик `stampMask()` обслуживает как RGB-материалы, так и ручные правки деревьев. Текущий режим определяет ветку по `mode` и `maskTool`.

`height` → `generateAutoMask()` → `autoRGB` → ручные `overrideA`/`maskRGB` → автоматический лес → `applyForestToMaterialMask()` → итоговый `maskRGB` + итог `treeAllowedAt()`.

## Подсистемы по функциям и строкам

### Размеры, aspect, pan/zoom и компас — строки 783–843

- `clampMapPan()`, `setMapZoom()`, `resetMapView()` управляют 2D-приближением и панорамированием.
- `terrainAxisScale()` переводит `terrainAspect` в масштаб осей.
- `terrainBrushRadii()`, `terrainBrushOffset()`, `terrainBrushDistance()` сохраняют физически круглую кисть на прямоугольном поле.
- `terrainWorldDimensions()` возвращает реальные ширину и высоту в метрах.
- `applyTerrainCanvasAspect()` меняет CSS-размер canvas без изменения квадратной сетки данных.
- `setTerrainAspect()` — единственная рекомендуемая точка смены aspect.
- `updateCompassLanguage()` и `setCompassAxes()` локализуют и вращают компас.

### Защита от «уплощения» повторных штампов — строки 848–871

- `heightMaximum()` и `refreshVisualPeak()` отслеживают фактическую вершину.
- `beginSculptStroke()`, `advanceSculptStroke()`, `endSculptStroke()` поддерживают динамический потолок активного штриха.
- `activeSculptPeak` нужен, чтобы повторные клики пирамидой, конусом или горой продолжали наращивать высоту, а не упирались в старый `pPeak` и не превращались в плоскую площадку.
- Новые поднимающие инструменты должны использовать тот же динамический предел внутри `applyStampAt()`.

### История Undo/Redo — строки 1003–1055

- `captureHistoryState()` сохраняет высоты, материалы, ручные флаги, деревья, aspect, геоданные и выбранный шаблон.
- `snapshot()` кладёт состояние в `undoStack`, очищает `redoStack`; лимит истории — 18.
- `restore()` восстанавливает все связанные массивы и метаданные.
- `doUndo()` / `doRedo()` используются верхними кнопками и Ctrl/Cmd+Z, Ctrl/Cmd+Y, Shift+Cmd+Z.
- Если новое состояние не попало в `captureHistoryState()`, Undo будет восстанавливать проект неполностью.

### Формы, острова и постобработка — строки 1057–1753

- `shapeField(kind,x,y)` содержит ветки всех шаблонов. Новая форма должна получить уникальный `data-template` в DOM и ветку здесь.
- `makeTemplate(kind)` заполняет `height`, выполняет naturalize и пересобирает зависимые маски.
- В HTML сейчас есть формы: архипелаг, атолл, полуостров, фьорд, каньон, кратер, шельф, континент, вулканический конус, кальдера, речная дельта, двойной кратер, кольцевой остров, дюнное поле, два острова, S-бухта, озёрный бассейн, тектонический разлом, коралловая цепочка, квадрат и пустой океан.
- В меню островов 24 реальных и фантастических варианта; их параметры также обрабатывает `shapeField()` через `islandKind`.
- Глобальные проходы: `applyErosion()` 1602–1631, `applyTerraces()` 1632–1646, `applyDunes()` 1647–1661, `applyNoiseDetail()` 1662–1675.
- `mirrorHeight()` 1676–1694 отражает не только высоту, но и связанные material/tree данные.
- `importHeightmapFile()` 1695–1720 импортирует grayscale PNG/JPEG и заменяет текущее поле.
- `wireBaseExtras()` 1721–1753 связывает эти кнопки с UI.

### Режимы редактора — строки 1755–1794

- Обработчики `[data-tool]` и `[data-mask]` выбирают текущий инструмент.
- `show2d(kind)` переключает `height`, `mask`, `trees`, canvas, легенды, drawer и активные вкладки.
- Для добавления нового режима нужно обновить минимум header, `show2d()`, `syncTerrainContext()` и drawer/icon mappings.

### Реальная карта — строки 1796–2454

Выделение:

- `setGeoStatus()` обновляет сообщения карты.
- `renderGeoSelection()` рисует текущий rectangle/polygon/freehand.
- `clearGeoSelection()`, `finishGeoSelection()`, `undoGeoPoint()` управляют выделением.
- `setGeoMode()` включает `rectangle`, `polygon`, `freehand` или `pan`.
- `handleGeoClick/Down/Move/Up()` реализуют ввод. Правая кнопка всегда панорамирует; в режиме Pan карта двигается ЛКМ.

Карта и слои:

- `GEO_BASEMAP_ORDER` и `GEO_RASTER_BASEMAPS`, строки 773–774 и 1912–1916.
- `setGeoBasemap()` / `cycleGeoBasemap()`, строки 1918–1962.
- `ensureGeoVectorBasemap()`, строки 1964–2008, лениво загружает MapLibre.
- `updateGeoMapLanguage()` меняет подписи векторной карты при RU/EN.
- `initGeoMap()`, `showGeoMap()`, `backFromGeoMap()`, строки 2010–2038.

Поиск:

- UI: строки 482–486.
- `searchGeoMap()`, строки 2110–2141; результаты рисует `renderGeoSearchResults()`.
- Используется `AbortController`, защита от устаревших ответов, небольшой cache и ограничение частоты запросов.

Высоты и импорт:

- геометрия polygon: `geoPointInPolygon()`, 2145–2160;
- Open-Meteo: 2162–2176 и 2257–2298;
- Terrarium: 2177–2256;
- bilinear sampling: `geoGridSample()`, 2299–2306;
- сглаживание маски острова: `geoBlurIslandMask()`, 2307–2337;
- rasterize выделения: `geoBuildIslandMask()`, 2338–2379;
- берег/шельф: `geoIslandCoastHeight()`, 2380–2387;
- итоговый импорт: `importGeoSelection()`, 2388–2454.

Опция `#mapMakeIsland` окружает выбранную область морем и формирует сглаженный шельф. Для freehand/polygon используется реальный контур; для rectangle сохраняется прямоугольник и его aspect.

### Скульпт высоты — строки 2455–2661 и 2755–2806

- `applyStampAt()` — единая математическая реализация всех инструментов.
- `stampHeight()` применяет текущую симметрию X/Y/radial и вызывает `applyStampAt()` для каждой копии.
- Инструменты разбиты в DOM на BASIC, SHAPE, DETAIL и STAMPS, строки 528–597.
- `pointerCanvasPos()` и `pointerPos()` переводят курсор в координаты сетки с учётом zoom/pan/aspect.
- Между событиями pointermove штампы интерполируются с шагом около `radius * 0.16`, поэтому хребты и реки непрерывны.
- ПКМ, средняя кнопка или Shift+ЛКМ панорамируют; колесо меняет zoom; Alt/Ctrl/Cmd+колесо меняет радиус кисти.
- После height stroke при включённом `#autoMask` нужно пересчитать автоматические материалы, не затрагивая ручные override.

Как добавить новый инструмент скульпта:

1. Добавить кнопку с уникальным `data-tool` в подходящий `<details class="tool-menu">`.
2. Добавить ветку в `applyStampAt()`.
3. Если инструмент поднимает рельеф, использовать динамический `activeSculptPeak`.
4. Добавить описание в `TOOL_EN` и `TOOL_RU`, строки 3968–3970.
5. Добавить иконку в `TOOL_ICONS`, строки 4141–4155.
6. При необходимости обновить `syncTerrainContext()` для показа `pSharp`, `pLow` или `pStrength`.
7. При желании добавить hotkey в `TOOL_HOTKEYS`, строка 3408.

### Материалы — строки 2662–2869 и 2930–2944

Это главный ответ на вопрос «где логика материалов»:

- DOM панели: строки 638–658.
- Выбор material tool: обработчики `[data-mask]`, строки 1755–1772.
- `normalizeMaterialPixel()`, строки 2662–2672: нормализация ручного RGB до суммы 255. Автоматический `[0,0,0]` не проходит через неё, потому что обозначает внешний detail 3.
- `stampMask()`, строки 2673–2753: ручное рисование R/G/B, smooth, erase; здесь же tree tools.
- `generateAutoMask(resetOverrides)`, строки 2807–2830: базовая авто-маска по высоте и уклону.
- `generateSlopeAutoMask()`, строки 2832–2855: более явное распределение по крутизне/высоте.
- обработчики кнопок mask panel: строки 2856–2869.
- `applyForestToMaterialMask()`, строки 2930–2944: финальная связь леса с B/detail 2 и открытой травой/detail 3.
- отображение RGB: ветки `render2d()` в строках 2962–3039.
- экспорт PNG: `buildMaterialMaskCanvas()`, строки 3132–3144.

Семантика ручного редактирования:

- При рисовании R/G/B `overrideA[i]` становится 255.
- Erase сбрасывает `overrideA[i]` и возвращает `autoRGB`.
- Автоматические пересчёты должны пропускать клетки с ручным override.
- `maskLandOnly` и `maskSeaOnly` ограничивают рисование относительно `pSea`.
- Нельзя использовать alpha PNG как материал: экспорт полностью непрозрачный, веса хранятся именно в RGB. `[0,0,0]` зарезервирован для detail 3/open grass; остальные валидные пиксели нормализованы до 255.

### Деревья — строки 2673–2753 и 2906–2961

- DOM панели: строки 660–676.
- `treeAdd`, `treeBlock`, `treeErase` находятся внутри `stampMask()`.
- `buildAutomaticForestMask()`, строки 2906–2929: процедурный лес по density, patch size, seed, высоте и уклону.
- `applyForestToMaterialMask()`, строки 2930–2944: согласует лес с vegetation material.
- `regenerateAutomaticForest()`, строки 2945–2954: новый `forestSeed`, новая auto tree mask и материалы.
- `treeAllowedAt()`, строки 2955–2961: сначала учитывает ручной `treeMask`, затем `treeAutoMask`.
- В tree render белое = деревья разрешены, тёмное = запрещены; контуры высот через 20 м включаются `#showTreeContours`.
- Экспорт: `buildTreeMaskCanvas()`, строки 3145–3158; smoothing отключён, чтобы сохранить бинарность.

### 2D-рендер — строки 2871–3039

- `heightColor()` задаёт палитру море → берег → низменность → горы.
- `reliefPixel()` рассчитывает hillshade.
- `isContourPixel()` / `shadeContourPixel()` добавляют линии высот.
- `terrainSlopeAt()` используется материалами и лесом.
- `render2d()` является единой точкой рисования height, material и tree режимов.
- Canvas сначала формируется в `ImageData(G,G)`, затем выводится с 2× supersampling.
- Золотой контур в tree mode — граница берега, не часть экспортируемой маски.
- Курсор кисти рисуется с aspect-correct радиусами; не заменять его обычным `ctx.arc()` без учёта aspect.

### 3D-превью — строки 3040–3105

- Это CPU Canvas 2D painter, несмотря на старые переменные `threeReady`, `mesh3` и устаревший README.
- `project3d()` делает собственную проекцию.
- `update3d()` сортирует ячейки back-to-front, красит квадраты через `heightColor()` и hillshade.
- Шаг сетки ограничивает нагрузку примерно уровнем 192 samples по стороне.
- ЛКМ вращает; прочие кнопки панорамируют; колесо меняет distance.
- `update3dCompass()` синхронизирует компас с камерой.
- Направление горизонтального drag задаётся строкой 3101: `theta=drag3.t-dx*.007`.

### Экспорт и проект — строки 3106–3286

- `bilinearField()` и `resampleHeight()` переводят `G×G` в `OUT×OUT`.
- `writeEXR()` создаёт одноканальный float EXR с каналом `Y` без внешней библиотеки.
- `buildMaterialMaskCanvas()` экспортирует нормализованный RGB PNG.
- `buildTreeMaskCanvas()` экспортирует чёрно-белый PNG.
- `buildHeightPreviewCanvas()` создаёт нормализованное grayscale PNG-превью, не метрические данные.
- `projectData()` описывает JSON-формат проекта version 2.
- `exportBundle` складывает EXR, material PNG, tree PNG, height preview, project JSON и README в ZIP.
- `loadProject` поддерживает форматы `TERRA GEN SCULPT` и старый `TERRA/FORGE SCULPT`.
- `#flipY` применяется ко всем экспортируемым raster/EXR данным, но не меняет рабочие массивы.

JSON-проект сохраняет:

- `grid`, sea/land/peak, seed, template/island kind;
- world size, terrain aspect, export size, preview scale;
- настройки material preview и contours;
- `geoSourceMeta`;
- настройки леса;
- base64-копии `height`, `maskRGB`, `overrideA`, `treeMask`, `treeAutoMask`.

Если появляется новое авторитетное состояние, его нужно добавить одновременно в `projectData()`, загрузку проекта и историю Undo/Redo.

### UI helpers, hotkeys, grid и startup — строки 3290–3557

- `TOOL_TIPS` — старый русский fallback; активные двуязычные описания находятся ниже в `TOOL_EN/TOOL_RU`.
- `updateMapSizeInfo()` обновляет размеры, HUD и footer с учётом aspect.
- `selectTool()` включает инструмент, открывает его группу и возвращает режим height.
- `TOOL_HOTKEYS`: 1–0 выбирают основные инструменты; `[`/`]` меняют радиус; `-`/`=` меняют силу.
- `resizeGrid()` согласованно пересоздаёт все typed arrays.
- `toggleSym()` управляет X/Y/radial symmetry.
- brush presets хранятся в localStorage под `terra-gen-brush-presets`.
- Startup 3543–3557 намеренно не генерирует тяжёлый остров: заполняет море и ждёт выбора пользователя. Не возвращать тяжёлую генерацию в синхронную загрузку страницы.

### Контекстные панели — строки 3560–3603

`syncTerrainContext()`:

- показывает только `.context-height`, `.context-mask`, `.context-trees`, `.context-map` или `.context-3d`;
- показывает `pSharp` только для mountain;
- показывает target level только для level-based tools;
- скрывает strength там, где он не нужен;
- обновляет help текущего инструмента.

Если новая настройка зависит от режима или инструмента, добавлять её логику сюда, а не разбрасывать `style.display` по обработчикам.

### Локализация — строки 3605–4137

- Блок 3605–3880 неактивен из-за раннего `return`; это legacy. Не добавлять туда новые переводы.
- Активный блок — `<script id="terraGenCompleteI18n">`, строки 3882–4093.
- Английский — канонический исходный язык DOM.
- `RU` содержит перевод английских строк; `EN` строится обратным словарём.
- `TOOL_EN/TOOL_RU` — описания sculpt tools.
- `MASK_EN/MASK_RU` — описания material/tree tools.
- `ID_TIPS_EN/ID_TIPS_RU` — точные tooltips по `id`.
- `translateNode()` локализует текст и `placeholder`, `aria-label`, `title`.
- `MutationObserver` переводит динамически добавленный/изменённый текст статуса.
- `setLang()` вызывает также `updateGeoMapLanguage()`, поэтому подписи векторной карты должны меняться вместе с UI.
- Меню языка и его позиционирование находятся в строках 4094–4137. Оно позиционируется относительно кнопки и имеет высокий z-index.

Как добавить видимый текст:

1. Писать канонический текст в HTML/JS на английском.
2. Добавить точный перевод в активный `RU` или в специализированный словарь.
3. Для кнопки/поля с особым смыслом добавить tooltip в `ID_TIPS_EN` и `ID_TIPS_RU`.
4. Для динамической фразы использовать стабильную английскую основу, чтобы `canonicalEnglish()` мог её распознать.
5. Не редактировать legacy `MAP_RU` в неактивном блоке.

### Lucide и выезжающие панели — строки 4138–4228

- `TOOL_ICONS` сопоставляет `data-tool` имени Lucide.
- `MASK_ICONS` — material/tree tools.
- `ACTION_ICONS` — режимы и служебные кнопки по `id`.
- `iconify()` сохраняет текст в `<span class="icon-label">`; для sculpt buttons названия рядом с иконкой должны оставаться видимыми.
- `fallbackMissingIcons()` заменяет отсутствующую иконку на `sparkles`.
- `setDrawer()` открывает нужную панель и при необходимости переключает режим.

- Добавляя кнопку, сначала дайте ей понятный текст и `id`/`data-tool`, затем внесите mapping в соответствующий icon object.

## Безопасный шаблон мутации состояния

Для нового пользовательского действия используйте такой порядок:

1. Проверить входные данные и завершить все потенциально падающие сетевые операции.
2. Вызвать `snapshot()` один раз перед первой реальной мутацией.
3. Изменить авторитетный массив/параметр.
4. Если изменилась высота: `refreshVisualPeak()` и пересчитать только автоматические material/tree области.
5. Если изменились деревья: согласовать B/detail 2 через `applyForestToMaterialMask()`.
6. Выставить `dirty3d=true` и `dirtyPreview3d=true` при изменении высоты/aspect.
7. Вызвать `render2d()`, `updateUndoButtons()`, при размерах — `updateMapSizeInfo()`.
8. Обновить status понятной локализуемой английской фразой.

Не делайте `snapshot()` внутри каждого пикселя, каждой точки интерполяции или каждого кадра drag.

## Проверки после изменений

В проекте нет test runner и build step. Минимальная автоматическая проверка без браузера:

```powershell
git diff --check
git status --short
```

Дополнительно по ситуации:

- Проверить, что inline scripts синтаксически разбираются JavaScript-парсером, если доступен Node.
- Проверить отсутствие дублирующихся HTML `id`.
- Проверить, что все `data-tool` имеют реализацию, перевод и Lucide mapping.
- Проверить, что все `data-template` имеют ветку в `shapeField()`.
- После изменения grid/load/save сравнить длины всех typed arrays.
- После material операции проверить, что R+G+B равно 255 либо намеренно равно 0 для detail 3/open grass; ручной `overrideA` не должен случайно стать нулевым material pixel.
- После treeAdd проверить одновременно белую tree mask и B=255.
- После real-map rectangle проверить `terrainAspect` и `terrainWorldDimensions()`.
- После RU/EN изменений проверить статический текст, динамический status, tooltips, compass и подписи векторной карты.

Визуальную проверку и production deploy выполняет владелец, если не попросил агента об этом отдельно.

## Производительность

- Не выполнять тяжёлую генерацию синхронно при startup; текущий быстрый startup в строках 3543–3557 намеренный.
- Полные циклы по `G*G` допустимы по завершении действия, но нежелательны на каждом pointermove, если можно обновить локальную область.
- `G=1024` означает более миллиона клеток и несколько многомегабайтных массивов; копии в history особенно дороги.
- История ограничена 18 состояниями; учитывайте стоимость при добавлении новых массивов.
- 3D painter не должен рисовать каждый cell при высоком `G`; сохраняйте bounded sampling.
- При сетевых запросах используйте отмену, cache и защиту от устаревших ответов, как в поиске карты.

## Известные особенности и техдолг

- `index.html` очень большой и монолитный. Пока владелец не попросил рефакторинг, не разбивать его на модули в рамках небольшой правки: это резко увеличивает риск регрессий и меняет deployment model.
- Legacy i18n block 3605–3880 оставлен, но не исполняется. Активную логику не дублировать туда.
- Переменные `threeReady`, `mesh3` и похожие названия — остатки старой версии; фактический 3D renderer dependency-free Canvas 2D.
- `README.md` не соответствует текущему продукту и не должен переопределять эту документацию.
- `resizeGrid()` бинаризует старую `treeMask` через порог; значение FORCE ADD 128 после интерполяции может стать 255 и потерять различие с FORCE BLOCK. При работах над resize это место требует отдельной проверки.
- Некоторые английские tooltip entries исторически содержат неточности; при затронутой UI-группе проверять смысл обеих локализаций, а не только наличие строки.
